# Required R oracle health and coordinate identity

Noether found that optimizer code zero alone was weaker than Julia's Tweedie
verdict. The test-only `test/parity/r_health.R` defines a structured point-fit
record: finite objective, free parameters and reported dispersion/power; raw
optimizer code/message; matching gradient dimension; scaled infinity-norm
gradient no larger than1e-5; and all free power logits inside[-20,20]. These
thresholds match the selected grouped Julia fitter's existing defaults.
It does not modify either engine, tolerances, fixture or optimizer controls.

The scale is max(1,abs(objective)). R free-coordinate counts must be observed
from the actual optimizer parameter names:0 fixed,1 shared,p per-species power.
Total R free coordinates must match Julia's information-criterion count.
Matching log likelihood alone does not prove this model identity.

A Hessian-PD diagnostic is recorded when available. The frozen comparison uses
se=FALSE, so an absent diagnostic stays explicitly not measured, not a PD pass.
This health record is not simulation recovery, coverage, global optimality or
an interval-quality verdict. Those remain separate required designs.

Pure R negative controls run locally without package loading or fits. They
reject code1, a code-zero large gradient, non-finite parameters/gradient,
wrong gradient dimension, invalid dispersion/power and an endpoint power
coordinate. The first run failed with the absent checker; after implementation
all controls pass. Numerical integration and actual frozen-R replay remain
pending and may fail these stronger requirements.

Gaussian and NB2 fixtures also now assert the already-retrieved R optimizer
flag. Full structured health coverage across the future finite manifest must
still be reviewed; these two assertions alone do not establish that coverage.
