# Required-case collections

Approved scope requires bounded execution and complete programme evidence.
Requiring every frozen case in a single process conflicted with the targeted
supervisor's 25-minute ceiling. The acceptance tool now verifies an explicit
collection of separately supervised runs. It does not change any estimator,
fixture, numerical tolerance, or required scientific case.

Each leaf uses the existing receipt, fixture, source and externally observed
exit checks. It may request a nonempty subset of required IDs only inside the
collection verifier. The collection requires an exact disjoint union of all
frozen IDs and unique run IDs. All source/runtime fields must agree except
absolute installation locations; every loaded checkout remains independently
bound to its supervisor plan. Current source and dependency content must match
each leaf. Consequently an engine edit invalidates affected earlier receipts
rather than allowing the collection to combine different candidates.

Failed batches remain ineligible, including their successful sibling commands.
Historical failures stay in retained evidence directories. This verifier takes
an explicit selection; it cannot prove that the caller disclosed all history.
Programme reconciliation must separately account for superseded attempts. It
does not automatically choose the best attempt or claim recovery denominators.

The full manifest remains `DRAFT_INCOMPLETE_NOT_FROZEN`. Eight regression tests
construct a synthetic complete contract in a temporary checkout and emit its
receipts through real supervised Python processes. Controls reject omitted,
unknown and duplicate cases, duplicate executable rows, external failure,
missing process/cell receipts, failed assertions, changed source and runtime or
contract mismatches. A standalone partial run is still rejected. These tests
verify acceptance machinery only; they do not validate R–Julia models.
