## What did NOT re-bind, and why

`namespace/export/loading_profile` was deliberately **not** re-run, per the task brief. Restating
the open question from `parity-defect-rebind-2026-09-02.md`: R's `loading_profile()`
(`loading-profile.R`) profiles a Λ entry gated on `fit$lambda_constraint` — it targets a
**confirmatory** (pinned-loadings) fit, the same gate `loading_ci()` uses. GLLVM.jl's
`loading_profile` surface exists (`src/confint_derived.jl:1134-1171`) but profiles an
**exploratory** (unpinned) fit — a different estimand, not a call-shape mismatch. Re-running any
batch against `gaussian_small` (exploratory) would not exercise R's actual accessor at all; the
open question is whether GLLVM.jl should gain a confirmatory-fit gate to match R's estimand, or
whether the exploratory-fit profile is a deliberate GLLVM.jl extension outside this parity family.
That is a maintainer estimand-scope call, not a re-run — left disposed as
`PARTIAL_PARITY_DEFECT_PENDING_DECISION`, untouched.
